# 기업 뉴스 조사

## 검색 계획서 구조
- 입력: 공시 문서 분석 보고서 (요청에 명시된 /reports/ 파일)
- 계열사 또는 사업부문을 4~6개의 조사 주제로 묶고, 주제마다 영문 slug를 정합니다. slug는 영문 소문자와 하이픈만 사용하여 계열사나 사업부문의 영문 이름을 짧게 정하고, 나머지를 묶은 주제는 `holding-and-others`처럼 정합니다. 요청에 slug 예시가 있으면 그 예시를 따릅니다.
- 주제마다 아래 항목을 작성합니다.
  + 주요 사안: 공시 분석 보고서에서 확인한 변화 2~3개
  + 검색어: 2~3개 (한국어 또는 영어)
  + 검색 목적
- 마지막에 주제 / slug / 검색어 / 검색 목적 4열 표로 정리합니다.
- 검색 계획서는 짧고 간결하게 작성합니다. 서론, 부연설명, 문장 장식은 넣지 않습니다.
- 이 단계에서는 웹 검색을 하지 않습니다.

## 뉴스 수집 절차
- 검색 계획서의 주제마다 news-researcher 서브에이전트를 task 도구로 한 번씩 호출합니다.
- 호출할 때는 주제명, 검색 계획서 경로, 저장 경로 `/reports/04-news/<slug>.md` 만 전달합니다. 검색 계획서 본문은 복사하여 전달하지 않습니다.
- 서브에이전트는 주제마다 최신 뉴스 기사를 최소 3개 수집하고, 아래 기사 요약 형식으로 저장합니다.

## 기사 요약 형식 (서브에이전트용)
- 파일 제목은 주제명으로 합니다.
- 기사마다 아래 항목을 작성합니다.
  + 제목, 매체, 발행일, URL
  + 사업적 관점의 요약 1문단 (6문장 이상): 무슨 일이 있었는지, 실적과 전략에 어떤 의미가 있는지
- 중복 기사와 같은 내용의 반복은 피하고, 서로 보완되는 기사 위주로 선별합니다.

## 뉴스 분석 보고서 구조 (메인 에이전트용)
- 저장된 주제별 파일을 read_file로 모두 읽은 뒤 작성합니다.
1. 요약: 최근 주요 이슈를 3~5줄로 요약
2. 주제별 주요 뉴스 (주제 수만큼 반복): 핵심 사안, 기사 요약, 공시 내용과의 연결
3. 회사 전체의 공통 이슈: 여러 계열사 또는 사업부문에 걸친 흐름
4. 참고 출처 목록: 기사 제목과 URL

## 출력 규칙
- 출력 언어: 한국어, 형식: 마크다운
- 출처는 웹 검색 결과만 사용하고, 모든 기사에 URL을 1개 이상 남깁니다.

## 금지 사항
- URL 없는 인용 또는 허위나 가상의 URL 작성
- 사전 학습 지식으로 기사 내용을 지어내는 것
- 서브에이전트 파일을 읽지 않고 기억만으로 종합
