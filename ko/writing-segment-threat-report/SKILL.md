# 사업부문별 경쟁 위협 분석

## 위협 검색 계획서 구조
- 입력: 본사의 공시 문서 분석 보고서 (요청에 명시된 /reports/ 파일)
- 본사에 위협이 될 수 있는 사안을 사업부문 기준으로 3~5개 주제로 묶고, 주제마다 영문 slug를 정합니다. slug는 영문 소문자와 하이픈만 사용하여 사업부문의 영문 이름을 짧게 정합니다. 요청에 slug 예시가 있으면 그 예시를 따릅니다.
- 주제마다 아래 항목을 작성합니다.
  + 대상 사업부문
  + 주요 경쟁사 후보: 공시 분석 보고서에 언급된 경쟁사를 우선 적고, 언급이 없으면 '검색으로 확인'으로 표기
  + 위협 사안: 2~3개
  + 검색어: 2~3개 (한국어 또는 영어)
  + 검색 목적
- 마지막에 주제 / slug / 주요 경쟁사 후보 / 검색어 / 검색 목적 5열 표로 정리합니다.
- 검색 계획서는 짧고 간결하게 작성합니다. 서론, 부연설명, 문장 장식은 넣지 않습니다.
- 이 단계에서는 웹 검색을 하지 않습니다.

## 조사 절차
- 검색 계획서의 주제마다 competitor-researcher 서브에이전트를 task 도구로 한 번씩 호출합니다.
- 호출할 때는 주제명, 검색 계획서 경로, 본사 공시 분석 보고서 경로, 저장 경로 /reports/06-threats/<slug>.md 만 전달합니다. 파일 본문은 복사하여 전달하지 않습니다.
- 서브에이전트는 검색 계획서의 해당 주제 검색어로 web_search를 실행하고, 아래 '사업부문 위협 보고서 구조'로 저장합니다.
- 메인 에이전트는 저장된 파일을 read_file로 모두 읽고, 아래 '위협 분석 종합 보고서 구조'로 종합합니다. 빠진 주제가 있으면 같은 서브에이전트를 한 번 더 호출하여 보완합니다.

## 사업부문 위협 보고서 구조 (서브에이전트용)
- 파일 제목은 주제명으로 합니다.
1. 요약: 이 사업부문의 경쟁 환경과 가장 큰 위협을 3줄로 요약
2. 주요 경쟁사 현황: 경쟁사마다 최근 동향, 투자, 수주 또는 계약, 생산능력 변화
3. 시장 및 산업 동향: 수요, 가격, 규제, 공급망 변화
4. 본사 사업부문에 대한 잠재적 위협
5. 대응 시사점
6. 참고 출처 목록

마지막에는 위협 요인 / 위협 수준(상/중/하) / 근거 / 본사 시사점 4열 표를 넣습니다.

## 위협 분석 종합 보고서 구조 (메인 에이전트용)
1. Executive Summary
2. 사업부문별 경쟁 환경과 위협 (주제 수만큼 반복): 주요 경쟁사, 핵심 위협, 근거
3. 사업부문 간 공통 위협: 여러 사업부문에 걸친 흐름 (환율, 원자재, 규제, 공급망 등)
4. 위협 우선순위
5. 대응 시사점
6. 참고 출처 목록

위협 우선순위에는 아래 표를 반드시 포함합니다.

| 사업부문 | 주요 경쟁사 | 핵심 위협 요인 | 위협 수준(상/중/하) | 대응 우선순위 |
|---|---|---|---|---|

## 출력 규칙
- 출력 언어: 한국어, 형식: 마크다운
- 출처는 입력 보고서와 웹 검색 결과만 사용합니다. 입력 보고서의 근거는 (출처: /reports/파일명), 웹 검색의 근거는 (출처: URL) 형식으로 표기합니다.
- 뉴스 요약 자체가 목적이 아니라, 위협 요인의 식별, 정량 및 정성 근거, 시사점에 초점을 둡니다.
- 언론 기사, 기업 IR 및 보도자료, 정부 및 국제기구 자료, 산업 조사 보고서를 근거로 사용합니다. 나무위키, 위키백과 같은 사용자 편집 사이트는 근거로 사용하지 않습니다.
- 중복 출처는 최소화하고 서로 보완되는 출처를 활용하며, 가능하면 한국과 글로벌 출처를 균형 있게 활용합니다.

## 금지 사항
- 사전 학습 지식 또는 추정으로 출처 없이 사실 주장
- URL 없는 인용 또는 허위나 가상의 URL 작성
- 서브에이전트 파일을 읽지 않고 기억만으로 종합
